# 10 组编程配对复现结果

本机 Qwen3.5 4B 完成了全部 10 组独立实验。两种方法在最终留出题上的完整通过率都是 0%，十组全部打平。这次小规模实验没有观察到论文报告的正向收益。由于两组成绩都落在最低分，实验也不足以判定改进笔记是否有效。

## 主结果

| 评测对象 | 完整通过的作答 | 留出通过率 |
|---|---:|---:|
| 每组共同的源阶段终点 | 0 / 100 | 0% |
| 无 SIM，继续改进两轮 | 0 / 100 | 0% |
| 有 SIM，继承笔记并继续更新两轮 | 0 / 100 | 0% |

每个分支每组面对两道相同的留出题，每题独立生成五次程序。一次作答必须通过该题全部测试。十个组内差值全部为 0，平均差值为 **0 个百分点**。精确符号秩检验没有非零差值可用于区分两组。程序按约定返回 p = 1，机械计算的零宽区间不代表真实效果已被精确测定。

## 为什么两边都是零

一道留出题要求在多个整数出现次数相同时，依次按出现跨度和首次出现的位置决定答案。另一道要求正确计数达到指定长度的极大连续递减区间。前者包含 131 个输入，后者包含 393 个输入。

- 有笔记的 100 份最终作答中，65 份无法按要求解析为 Python 表达式。无笔记的 100 份中有 74 份遇到同样的问题。每次输出上限为 160 个 token，分别有 21 和 27 份最终作答触及上限。这两类计数可能重叠。
- 有笔记组有 7 份最终作答答对了至少一个用例，无笔记组有 4 份。两组都没有任何一次答对整道留出题。部分通过是事后诊断，主指标始终使用整题通过率。
- 在正式样本之外，两份独立编写的正确表达式在同一镜像中分别通过 131/131 和 393/393 个用例。固定返回 0 的错误答案在两题都被判整题失败。在优化题上，模型自身也有 17 次作答获得整题通过。

## 实际运行和核验

正式实验约耗时 3 小时 10 分钟，共记录 720 次模型调用，包括 600 次生成程序和 120 次提出、选择修改。十个独立源运行得到了十份不同的起始指导，各带有 1 或 2 条已选修改的尝试记录。每组两个目标分支使用同一源指导、相同题目、对应采样种子和相同预算。

核验程序检查了 60 个优化轮次、200 次最终留出作答与 100 次共同起点作答。两个分支完成选稿后才使用留出题。新建的断网评分容器将全部 300 份留出作答重新执行了一遍，每份的正确用例数和整题得分都与原始记录一致。

## 这次实验能说明什么

论文使用 Gemini、Terminal-Bench 和可编辑的智能体工作流程。本次按约定改用本机量化 Qwen、六道自编的短 Python 题，以及可编辑的自然语言指导。每阶段两轮、每轮两个候选，最终使用两道留出题。模型须在有限输出长度内写成单个表达式。每组有笔记和无笔记的比较成立，但两道留出题和全零的主指标使这个比较难以测出方法差异。论文报告的平均领先 2.36 分来自另一套实验。

相同目录中的 `实验说明.md` 说明设计与运行方式。`results/final_trials.csv` 保存 200 条终点评分，`results/observations.sqlite` 保存逐次请求、模型回答、反馈和源检查点。`results/summary.json` 和 `results/audit.json` 分别保存统计与核验结果。可运行 `python audit_results.py --regrade` 再次核验。
